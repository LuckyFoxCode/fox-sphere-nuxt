# fox-sphere-nuxt

Twitch-бот и оверлей для OBS: Nuxt 4 + Pinia + Tailwind 4, бот на Node + TypeScript, Prisma + SQLite (драйвер libSQL, без компиляции).
Без Docker, работает на Windows и Mac. Сейчас есть вход через Twitch, чат, XP за сообщения и виджеты оверлея на Socket.io: шапка стрима, чат, алерты и рулетка.

## Структура

```
app/        Nuxt: pages, stores (Pinia); /overlay — страница для OBS (прозрачный фон, ssr: false)
server/     Nitro: вход через Twitch (OAuth) и API админки
bot/        бот (отдельный pnpm-пакет)
shared/     общий код бота и Nuxt
prisma/     schema.prisma (SQLite)
data/       dev.db / prod.db (в .gitignore)
scripts/    вспомогательные скрипты
```

## Быстрый старт

Нужны Node 22+ и pnpm 10.

```bash
pnpm install
cp .env.example .env.development   # заполнить
cp .env.example .env.production     # заполнить: порт 3000, prod.db, BOT_ENABLED=true
pnpm db:push:dev                    # создать data/dev.db
pnpm dev
```

(Windows PowerShell: `Copy-Item .env.example .env.development`.)

## Окружения

| | dev | prod |
|---|---|---|
| env-файл | `.env.development` | `.env.production` |
| порт Nuxt | 3001 | 3000 |
| база | `data/dev.db` | `data/prod.db` |
| бот | **выключен** (`BOT_ENABLED=false`) | включён |
| префикс команд | `!t` (`!tcoins`, `!tprofile`) | `!` |

Бот в dev по умолчанию выключен, чтобы не отвечать в чат дважды. Чтобы включить — `BOT_ENABLED=true` в `.env.development`.
Оверлей: `http://localhost:3001/overlay` (dev), `http://localhost:3000/overlay` (prod).

## Скрипты

- `pnpm dev` — Nuxt и бот вместе (concurrently)
- `pnpm build` — сборка Nuxt с `.env.production`
- `pnpm start` — Nuxt (`.output`) и бот в prod-режиме
- `pnpm db:push:dev` / `pnpm db:push:prod` — применить схему Prisma к нужной базе
- `pnpm db:copy-prod-to-dev` — скопировать `data/prod.db` в `data/dev.db`
- `pnpm prisma:generate` — сгенерировать клиент Prisma (в `generated/`, в git не попадает)
- `pnpm db:import` — перенести зрителей из дампа Postgres старого fox-sphere (см. ниже)

## Импорт зрителей из старого fox-sphere

Скрипт читает data-only дамп `pg_dump` (по умолчанию `data/prod-pg-dump.sql`) и переносит зрителей, героев, историю монет и XP, watch streak и `SystemState` (соответствие полей — `docs/spec.md`, 1.2). Токены Twitch и legacy-таблицы не переносятся.

```bash
pnpm db:import                          # пробный прогон по dev.db: что изменится и что не сошлось
pnpm db:import --apply                  # записать (перед этим делается копия базы в data/)
pnpm db:import --db data/prod.db        # другая база
pnpm db:import --file data/other.sql    # другой дамп
```

Повторный запуск не дублирует строки. Балансы совпадающих зрителей **перезаписываются** значениями из дампа, поэтому после перехода на нового бота старый дамп накатывать нельзя. На время `--apply` бота этой базы лучше остановить.

## База данных и драйвер

SQLite подключается через `@prisma/adapter-libsql` (внутри — `@libsql/client` с готовыми бинарниками для Windows/Mac/Linux). Он **не требует компиляции**: Python, Visual Studio Build Tools и node-gyp не нужны. Раньше был `better-sqlite3`, который собирался из исходников и падал на Windows без Build Tools — его в проекте больше нет.

- `DATABASE_URL` — путь к файлу в формате `file:./data/dev.db` (относительно корня репозитория).
- `prisma db push` и `prisma generate` драйвер не используют (у Prisma свой движок), поэтому `db:push:*` работают без адаптера.
- Адаптер подключается в `bot/src/db.ts`; для Nuxt-сервера (Nitro) используй тот же `PrismaLibSql`.
- В `package.json` в `pnpm.ignoredBuiltDependencies` стоит `better-sqlite3`: Nuxt (через db0) тянет его как необязательную зависимость, но pnpm не запускает его сборку.

SQLite открывается из двух процессов (Nuxt и бот), поэтому бот включает `PRAGMA journal_mode=WAL`.
Секреты не коммитятся: в git только `.env.example`.

## Оверлей и Socket.io

Сервер Socket.io живёт в боте (`bot/src/socket.ts`, встроенный HTTP Node, без Express) и стартует всегда, даже при `BOT_ENABLED=false`. Порт — `SOCKET_PORT` (по умолчанию 3002; Nuxt и бот читают одну переменную). По умолчанию слушает только `127.0.0.1`. Контракты событий — `shared/events.ts`:

| Событие | Когда | Payload |
|---|---|---|
| `stream:xp-updated` | стрим получил XP | `lvl, newXp, maxXp, startXp` |
| `twitch:follow` | новый фолловер | `userId, username` |
| `twitch:raid` | канал рейдят | `raiderId, raiderName, viewers` |
| `twitch:reward-redeem` | активирована награда за баллы | `userId, username, rewardTitle, redemptionId` |
| `twitch:sub` | подписка, resub или подарок | `kind, username, tier` + `userId`, `months` или `amount` |
| `twitch:bits` | cheer (Bits) | `username` (`null` — анонимно), `bits` |
| `roulette:spin-result` | началось вращение рулетки | `userId, username, prizeType, coinAmount, xpAmount, jackpotWon, jackpotTotalAfter` |
| `stream:jackpot-updated` | лента остановилась или банк пополнен (сундук рыбалки) | `jackpotTotal` |
| `fishing:chest` | на рыбалке пойман сундук | `userId, username, coinAmount, lang` |
| `twitch:golden-beer` | `!pivo` выбил золотое пиво | `userId, username, goldenBeers, tier, isNewTier` |
| `stream:xp-boost` | буст XP включён или отменён | `multiplier, expiresAt` или `null` |
| `twitch:timer` | запущен `!timer` | `title, color, endsAt` |
| `twitch:timer-stop` | `!stoptimer` | нет |

При каждом подключении оверлей запрашивает текущее состояние стрима (`stream:get-system-state`). Весь XP, который зритель получил за сообщение, прибавляется и стриму (`SystemState`, `bot/src/stream.ts`); порог уровня `lvl` стрима — `1000 × (1 + 2 + … + lvl)`. О новом уровне стрима prod-бот пишет в чат, dev-бот только в лог.

Буст XP: `!xpboost [5–60]` (в dev `!txpboost`) включает ×2 за сообщения на указанные минуты (по умолчанию 30), `!xpboost off` отменяет; команды только для стримера и модераторов. Новый уровень стрима включает буст на 30 минут сам, если другого нет. Множитель получают и зритель, и стрим, но только за XP сообщения. Состояние лежит в `SystemState` (`xpBoostMultiplier`, `xpBoostExpiresAt`), событие `stream:xp-boost` (`{ multiplier, expiresAt }` или `null`), при подключении оверлей спрашивает `stream:get-xp-boost`. Чип «×2 29:59» рисуется под шапкой, слева от карточки музыки, на `/overlay/stream` и в сцене. Код: `bot/src/xpBoost.ts`, `bot/src/commands/boost.ts`, `app/components/StreamXpBoost.vue`.

XP и уровень зрителя бот хранит в базе; о новом уровне prod-бот пишет в чат, dev-бот только в лог. Отдельного виджета для них на оверлее нет.

Клиент — плагин `app/plugins/socket.client.ts` (автопереподключение каждые 1–5 с без лимита), состояние виджетов — Pinia-сторы `app/stores/`.

### Добавить виджет в OBS

Все оверлеи с адресами (кнопка «Скопировать») и размерами собраны на главной: `http://localhost:3001/` (prod: порт 3000). Новый виджет добавляется в список `app/utils/overlays.ts`.

1. Запустите `pnpm dev` (dev) или `pnpm start` (prod).
2. В OBS: Источники → «+» → **Браузер**. URL шапки стрима: `http://localhost:3001/overlay/stream` (prod: `http://localhost:3000/overlay/stream`). Банк рулетки, уровень и XP стрима стоят справа сверху и видны постоянно.
3. Ширина **1920**, высота **1080**. Фон прозрачный, свой CSS добавлять не нужно. Галочку «Выключать источник, когда не отображается» лучше снять.
4. Герои: источник `http://localhost:3001/overlay/heroes` (prod: порт 3000), 1920×1080, прозрачный фон (Phaser с `transparent: true`). Герои зрителей ходят по нижнему краю, над ними наклейка с ником и титулом и бумажный пузырь с последним сообщением (8 с). Зритель появляется после своего сообщения и уходит через 5 минут тишины. Каждый новичок получает бесплатного героя Assassin; `!buy hero robber` покупает (в dev `!tbuy`), `!use hero robber` надевает, `!shop` открывает окно магазина на оверлее `/overlay/shop` (12 с, в чат ничего не пишет). Бот кладёт активного героя в `chat:message` (`hero`), смену шлёт событием `hero:changed`. Код: `bot/src/heroes.ts`, `bot/src/commands/hero.ts`, `shared/heroes.ts`, `app/phaser/`, `app/components/hero/`. В `scene` герои идут нижним слоем. Новый герой: запись в `shared/heroes.ts` и `idle.webp`, `walking.webp`, `front.webp` в `public/assets/heroes/<id>/`.
4. Чат: второй источник «Браузер» с URL `http://localhost:3001/overlay/chat` (prod: порт 3000), 1920×1080, тот же прозрачный фон. Колонка 400 px слева внизу: до 5 сообщений, каждое живёт 18 с. Настоящие сообщения приходят от бота как событие `chat:message`.
5. Алерты: источник с URL `http://localhost:3001/overlay/alerts` (prod: порт 3000), 1920×1080. Follow, рейд, награда за баллы, подписки и сундук из рыбалки показываются по одному снизу по центру на 5 с (сундук — 5,5 с), со звуком (`public/assets/sound/`). Чтобы звук шёл в микшер OBS и там регулировалась громкость, включите в свойствах источника «Управление аудио через OBS».
6. Рулетка: источник с URL `http://localhost:3001/overlay/roulette` (prod: порт 3000), 1920×1080. Лента по центру появляется на каждое вращение, на джекпоте — экран на весь кадр со звуком `jackpot.mp3` (включите «Управление аудио через OBS»). Превью всех карточек: `/dev/roulette`.
7. Лотерея VIP: источник `http://localhost:3001/overlay/lottery` (prod: порт 3000), 1920×1080. Запускается командой `!runlottery` (в dev `!trunlottery`, только стример): заставка, прокрутка пяти барабанов, финал со списком победителей, всего 15 секунд при любом числе участников. Встаёт в очередь за рулеткой и алертами. Превью: вкладка «Лотерея» в `/dev/events`. Победители получают временный VIP до следующего розыгрыша; перманентные VIP не трогаются. `LOTTERY_TWITCH_VIP=false` отключает реальную выдачу VIP в Twitch (по умолчанию включена только в prod).
7. Таймер: источник с URL `http://localhost:3001/overlay/timer` (prod: порт 3000), 1920×1080. Колонка 400 px слева над чатом, пока таймера нет, пусто. Запуск в чате: `!timer [минуты] [цвет] [название]`, например `!timer 5 red BRB` (в dev `!ttimer`); цвета amber, blue, cyan, purple, red, rose; остановка `!stoptimer`. По окончании играет `timer-off.wav` (включите «Управление аудио через OBS»). Дедлайн хранится в `SystemState`, поэтому таймер переживает перезагрузку источника и рестарт бота; события `twitch:timer`, `twitch:timer-stop`, запрос `twitch:get-timer`. Код: `bot/src/streamTimer.ts`, `bot/src/commands/timer.ts`, `app/components/timer/`.
8. Если виджет не реагирует: нажмите «Обновить кэш текущей страницы» в свойствах источника и проверьте, что бот запущен и `http://localhost:3002/health` отвечает `ok`.

### Проверка без чата (эмулятор)

Откройте `http://localhost:3001/dev/events` (бот при этом должен работать, `BOT_ENABLED=false` подходит). Кнопки шлют события на сервер, он рассылает их оверлеям, а справа в окне видно превью `/overlay/stream`, `/overlay/roulette`, `/overlay/chat`, `/overlay/timer` или `/overlay/alerts` (переключатель над превью) на шахматном фоне. В колонке «Алерты» есть кнопки сундука из рыбалки (алерт и +200 в банк шапки), рейда, награды, подписки, resub, подарка (в том числе анонимного) и «Все подряд» для проверки очереди. Для шапки есть «Добавить XP стрима», «Повысить уровень стрима» и «Вернуть значения из базы», там же кнопки буста XP (включить, на 10 секунд, убрать); во вкладке «Таймер» — запуск с названием и цветом, короткий на 10 секунд (конец и звук), формат ЧЧ:ММ, остановка; в базу эмулятор ничего не пишет. Для чата есть форма сообщения (ник, цвет, уровень, роли, announcement, watch streak) и кнопки «по сообщению от каждой роли», «семь подряд» и «ссылка и длинное слово». В колонке «Рулетка» можно запустить вращение с выбранным призом, джекпот, случайный слот или три подряд, а также поменять банк в шапке и вернуть значение из базы. Там же «Рыбалка»: заброс с выбранным или случайным уловом (поклёвка через 3 с), ответы про кулдаун и выбор языка ответов; сообщения идут в чат оверлея, сундук — в алерты и банк шапки, XP — в шапку. Превью «Сцена» накладывает чат, шапку, рулетку и алерты друг на друга, как в OBS. Те же события увидит и источник в OBS. В prod эмулятор выключен (`NODE_ENV=production`; принудительно — `DEV_EVENTS=true/false`).

## Рулетка и банк

`!spin` (алиасы `!roll`, `!спин`, `!лудка`; в dev с префиксом `!t`: `!tspin`) стоит 100 монет, кулдаун 30 с на зрителя. 10 монет с каждого спина уходят в банк (`SystemState.jackpotTotal`), после джекпота банк начинается с 1000. `!spinstats` — статистика зрителя. Цены, веса и тайминги — `shared/roulette.ts`, спин в базе — `bot/src/roulette.ts`, пополнение банка из других игр — `addToBank` в `bot/src/bank.ts`.

Вращения идут по очереди: следующее начинается, когда оверлей убрал предыдущее. Ответ в чат, новый банк и XP-приз показываются в момент остановки ленты.

## Рыбалка

`!fish` (алиасы `!рыбачить`, `!рыбалка`; в dev `!tfish`) бесплатна, кулдаун 60 с на зрителя. Бот пишет, что удочка заброшена, через 10–30 с поклёвка сама решает исход и приходит вторым сообщением, «тянуть» ничего не нужно:

| Улов | Шанс | Что происходит |
|---|---|---|
| 25 монет | 30% | монеты зрителю (`CoinHistory`, `FISH`) |
| 70 монет | 10% | монеты зрителю |
| 100 монет | 0,8% | монеты зрителю |
| 20 XP | 25% | XP зрителю и стриму (`XpHistory`, `FISH`), без надбавок за роли |
| 40 XP | 9,7% | XP зрителю и стриму |
| сундук 200 монет | 2,5% | уходит в банк рулетки, зритель не получает ничего |
| сорвалась | 22% | ничего |

Своего виджета на оверлее у рыбалки нет: сообщения бота видны в чате, XP — в XP стрима. Заметное событие только сундук: сумма в банке шапки подпрыгивает с золотой подсветкой (во время вращения рулетки — после остановки ленты), а в `/overlay/alerts` идёт свой алерт (`fishing:chest`) — сундук открывается, из него летят монеты, ниже ник и «+200 coins to the bank», звук `streak.mp3`. Пока на сцене рулетка или джекпот, алерт сундука ждёт в очереди, остальные алерты проходят вперёд. Банк подпрыгивает при любом пополнении, в том числе от взноса со спина. Незавершённые забросы хранятся только в памяти и при перезапуске бота теряются. Веса и тайминги — `shared/fishing.ts`, тексты — `shared/i18n/`, команда — `bot/src/commands/fish.ts`, выплата — `bot/src/fishing.ts`.

## Пиво

`!pivo` (алиасы `!пиво`, `!beer`; в dev `!tpivo`) бесплатна, кулдаун 60 с на зрителя, повтор во время кулдауна молча пропускается. Монет и XP не двигает. С шансом 95% бот пишет в чат одну из пяти фраз про пиво, с шансом 5% — «GOLDEN BEER!»: счётчик `Viewer.goldenBeers` растёт на единицу (одним атомарным `UPDATE`), а в `/overlay/alerts` идёт алерт `twitch:golden-beer` после сообщения в чат.

Ступень по счётчику: 1 → fresh, 2 → dark, 4 → aged, 7 → golden, 13 → legendary (при 5% это в среднем 20/40/80/140/260 попыток). Алерт — янтарная наклейка с артом ступени (`public/assets/achievements/pivo/tier-N.webp`), ником, «{ступень} brew», числом `xN` справа и чипом «new tier», если этим пивом ступень выросла; висит 7 с, без звука (как в старом проекте). Подписи алерта английские, как у follow и raid. Фразы — `shared/i18n/` (`en` слово в слово из старого бота, `uk` и `ru` переведены), шанс, кулдаун и ступени — `shared/pivo.ts`, команда — `bot/src/commands/pivo.ts`, запись счётчика — `bot/src/pivo.ts`. Проверка без Twitch — раздел «Пиво» в `/dev/events`.

## Новые функции

Кратко, что появилось сверх рулетки, рыбалки и пива (подробности в разделах выше и в `docs/ROADMAP.md`). Команды даны для prod; в dev префикс `!t`.

- **Буст XP:** `!xpboost [5–60]` включает ×2 за сообщения, `!xpboost off` отменяет. Только стример и модератор. Новый уровень стрима включает буст сам. Чип «×2» на оверлее.
- **Таймер:** `!timer [минуты] [цвет] [название]` и `!stoptimer`. Оверлей `/overlay/timer`, в конце играет звук.
- **Лотерея VIP:** `!ticket`, `!tickets`, `!runlottery` (стример). Билет даёт недельный XP, победители получают временный VIP до следующего розыгрыша.
- **Герои:** `!shop`, `!buy hero <имя>`, `!use hero <имя>`. Герои зрителей ходят по оверлею `/overlay/heroes`. Отвечая в чат, бот тоже выходит на полосу со своим пузырём и титулом `SYSTEM BOT` (герой из записи бота в базе, без неё бесплатный; если бот пишет с аккаунта стримера, отдельного героя нет).
- **Профиль:** `!profile` показывает на оверлее карточку: герой, уровень, монеты, плашки ролей и самые редкие ачивки.
- **Ачивки:** считаются из существующих данных (отдельной таблицы нет), лучшие попадают на карточку профиля.
- **Роли:** `!addvip` / `!removevip` и `!addfounder` / `!removefounder` (стример и модератор, кулдаун 10 с). Founder даёт бонус XP за сообщения и плашку в чате; Twitch API для него нет, поэтому статус хранится только в базе.
- **Награды за баллы:** на любую награду бот отвечает в чат (только prod), а на оверлее идёт алерт.
- **Bits:** алерт «bits cheered» с ником и числом битсов (анонимно показывается как Anonymous), звук `bits.mp3`. Нужно право `bits:read`, оно уже в правах стримера; если Bits пришли раньше этого обновления, оповещения о них не было.
- **Звуки алертов:** лежат в `public/assets/sound/`, адреса в `ALERT_SOUNDS` (`app/utils/alerts.ts`). Звук подписки `sub.mp3` сделан синтезом и свободен от лицензий. Так же синтезирован `level-up.mp3`.
- **Level up зрителя:** отдельная карточка `LevelUpCard` 520 px в духе мини-профиля (крупный портрет героя, ник, герой и его уровень, переход уровня с кольцом и званием, полоса XP до следующего уровня, четыре стата героя; тег «new rank» при смене звания, 6,5 с), событие `user:level-up`. Бот шлёт его из `showXpAward` при любом повышении уровня: чат, рыбалка, приз рулетки, награда за стрик; в dev тоже (в чат в dev не пишется). Показывается в общей очереди алертов; кнопка есть в эмуляторе `/dev/events`, вкладка «Алерты».
- **Перенос данных:** `pnpm db:sync-old` забирает свежие данные из Postgres старого fox-sphere в `data/prod.db`. Без `--apply` это пробный прогон, с `--apply` запись (перед ней делается копия базы). Нужен `OLD_SSH_HOST` в `.env.production`, инструкция `docs/MIGRATION.md`.

Все алерты, в том числе подписку со звуком, можно проверить без Twitch в `/dev/events`.

## Языки ответов бота

Бот отвечает в чат на английском (`en`); есть украинский (`uk`) и русский (`ru`). Язык выбирается в админке, раздел «Настройки», и меняется за несколько секунд без перезапуска; выбор лежит в `SystemState.botLang`, а пока его нет, действует `BOT_LANG` из `shared/i18n/index.ts`. Все фразы лежат в `shared/i18n/en.ts`, `uk.ts`, `ru.ts` с общим типом `types.ts`: пропущенный перевод не пройдёт проверку типов. Бот берёт словарь через `messages()` из `bot/src/language.ts`. Все фразы на трёх языках рядом: `/dev/messages`. Команды и алиасы от языка не зависят. Из надписей оверлеев переводятся алерт сундука и лотерея: язык приходит вместе с событием и совпадает с языком бота.

## Вход через Twitch (два аккаунта)

- Бот: `http://localhost:3001/auth/twitch/login` (аккаунт бота; если бот — ваш основной аккаунт, это тот же вход).
- Стример: `http://localhost:3001/auth/twitch/broadcaster/login` (нужен `TWITCH_USER_ID`). Права: `shared/twitch.ts`.
- Оба входа используют один Redirect URL `http://localhost:3001/auth/twitch/callback`. Права запрашиваются в ссылке авторизации, в консоли dev.twitch.tv их настраивать не нужно.
- Один аккаунт = одна строка `TwitchToken`. Если бот и стример — один аккаунт (`TWITCH_BOT_ID` пуст или равен `TWITCH_USER_ID`), оба входа просят права обеих ролей.

## Админка

`http://localhost:3001/admin` (prod: порт 3000). Интерфейс на Nuxt UI, пускают только стримера.

**Настройка** в `.env.development` и `.env.production`:

1. `ADMIN_SESSION_SECRET` и `INTERNAL_SECRET`: две разные случайные строки не короче 32 символов. С `CHANGE_ME` вход закрыт. Сгенерировать одну:

   ```bash
   node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"
   ```

2. `TWITCH_USER_ID` — ваш Twitch ID (или `ADMIN_TWITCH_USER_ID`, если пускать нужно другой аккаунт). Вход идёт через тот же `TWITCH_BOT_REDIRECT_URI`, в консоли Twitch добавлять ничего не нужно.
3. Перезапустите и сайт, и бота: переменные читаются при запуске.

**Что есть.** Пульт эфира: буст XP на 5–60 минут и выключение (prod-бот пишет в чат ту же фразу, что на `!xpboost`); VIP-лотерея — билеты, прошлые победители и розыгрыш с подтверждением (то же, что `!runlottery`, нужен включённый бот); тестовые алерты и карточки на оверлей. Тесты ничего не пишут в базу и чат, работают и в prod без эмулятора, но видны на стриме.

**Игры** (`/admin/games`). Только просмотр: башня (бонус дня и все бонусы по очереди, этажи, боссы, попытки, правила), герои и прокачка, рулетка, рыбалка, VIP-лотерея, буст XP, пиво, монеты и опыт, ачивки. У каждой карточки строка «что это и зачем», подробности свёрнуты. Все числа берутся из `shared/`, тексты карточек — `app/utils/adminGames.ts`, башня — `app/components/admin/AdminTowerCard.vue`.

**Настройки** (`/admin/settings`). Язык ответов бота (en / uk / ru); цвета админки из готовых наборов (выбор запоминается в браузере, наборы — `app/utils/adminPalettes.ts`); подключения: отвечает ли бот, в чате ли он, сохранены ли входы Twitch бота и стримера, с кнопками повторного входа (после него бота нужно перезапустить). Сами токены в браузер не передаются. Там же копия базы: кнопка сохраняет базу этого окружения в `data/<имя>.backup-<дата>.db` (целостно, даже пока бот пишет) и показывает список копий; старые не удаляются, скачать через браузер нельзя, внутри есть токены Twitch. Чтобы вернуть копию: остановите сайт и бота, удалите файлы `<имя>.db-wal` и `<имя>.db-shm`, замените `<имя>.db` копией и запустите снова.

> После обновления проекта выполните `pnpm db:push:dev` (для боевой базы `pnpm db:push:prod`) до запуска: в `SystemState` добавилось поле `botLang`, без него бот и сайт не прочитают состояние стрима.

**Зрители** (`/admin/viewers`). Сколько всего зрителей, монет и XP, таблица с поиском по нику и сортировкой по монетам, уровню, активности или нику. Метки: `streamer`, `bot`, `follower` или `viewer`, `mod` и `sub` (по последнему сообщению), `founder`, `VIP`, `lottery VIP`, `ticket`. `follower` и `viewer` берутся не из базы: бот спрашивает фолловеров у Twitch токеном стримера и держит список 5 минут; нужен включённый бот и вход стримера, без них метки нет и страница пишет причину. На странице зрителя видно, с какой даты он фолловит. Ник открывает страницу зрителя (`/admin/viewers/<номер в базе>`, назад — по хлебным крошкам сверху; поиск и сортировка списка запоминаются): уровень, статистика игр, все ачивки с прогрессом, герои, стрики просмотров и вся история монет. Раздел только читает базу, изменить баланс из него нельзя. Данные обновляются кнопкой «Обновить».

**Команды** (`/admin/commands`). Все команды по группам с поиском по имени, алиасу, описанию или группе и фильтром по тому, кто может вызвать: все зрители, модератор и стример, только стример. У текстовых команд (таблица `TextCommand`) здесь меняются ответы на en, uk и ru (на каждом языке хотя бы один, до 500 символов; из нескольких бот берёт случайный) и включение. Переключатель сохраняется сразу, тексты — кнопкой «Сохранить», она появляется внизу карточки после правки; бот подхватывает правки примерно за 30 секунд, перезапуск не нужен. Свои `!gh`, `!tg`, `!project` и `!stack` вносите тут: нетронутые шаблоны помечены «заглушка». Правки лежат в базе того окружения, где открыта админка: тексты с dev (порт 3001) в боевую базу не попадают. Права, имена и фразы команд из кода только показаны. Новые команды, алиасы и кулдауны здесь пока не меняются.

**Как защищено.** Вход не просит у Twitch прав и не сохраняет токен, только сверяет ID. Сессия — зашифрованная cookie на 7 дней, ID проверяется на каждой странице и запросе; смена `ADMIN_SESSION_SECRET` завершает все сессии. Браузер говорит только с Nuxt, а тот — с ботом по `/internal/*` на порту сокета с `INTERNAL_SECRET`. Открывайте админку по тому же адресу, что в Redirect URL (`localhost`, не `127.0.0.1`).

**Палитра** — `app/app.config.ts` (`primary` — акцент, `neutral` — фоны и текст; любой цвет Tailwind), свои оттенки и скругления — `app/assets/css/admin.css`. Оверлеи эти настройки не затрагивают: стили админки подключают только её layout'ы (`app/layouts/`).

Код: `app/pages/admin/`, `app/components/admin/`, `server/api/admin/`, `server/utils/admin-session.ts`, `bot/src/internal.ts`, `bot/src/admin.ts`, `shared/admin.ts`, `shared/testEvents.ts`; раздел команд — `shared/commands.ts` (список команд из кода с ролями; новую команду бота нужно добавить туда, иначе не пройдёт проверка типов), `server/utils/text-commands.ts`; раздел зрителей — `shared/viewers.ts`, `server/utils/admin-viewers.ts`; настройки — `shared/settings.ts`, `server/utils/admin-settings.ts`, `server/utils/db-backup.ts`, `bot/src/language.ts`.

## Анонсы и шаутауты

Бот отправляет их через Helix от своего аккаунта (`bot/src/announcements.ts`), в канал `TWITCH_USER_ID`. Без этой переменной они выключены.

Настройка:

1. **Остановите бота и войдите заново.** Токен, выданный раньше, новых прав не получает. Для входа нужен только сайт: `pnpm dev:web` (dev) или `pnpm build`, затем `pnpm start:web` (prod, порт 3000).
   - под аккаунтом бота: `/auth/twitch/login` (права `moderator:manage:announcements`, `moderator:manage:shoutouts`, `user:bot`);
   - под аккаунтом стримера: `/auth/twitch/broadcaster/login` (`channel:bot`);
   - если бот и стример — один аккаунт, достаточно любого из двух входов.
2. **Сделайте бота модератором**: в чате канала `/mod <ник бота>` от имени стримера (для одного аккаунта не нужно).
3. Запустите бота. У dev и prod разные базы, поэтому вход нужен в каждом окружении.

Если в логе бота отказ: `403` — бот не модератор (`/mod`); `401` или сообщение о недостающем scope — вход не повторён или бот не перезапущен после него; `429` — лимит Twitch (шаутаут раз в 2 минуты, одному каналу раз в час); `400` на шаутауте — обычно стрим не идёт или на нём нет зрителей.

**Follow, награды и подписки** бот получает по EventSub вместе с рейдами (`bot/src/eventsub.ts`, токен стримера) и показывает в алертах. За follow prod-бот благодарит в чате, dev-бот только пишет в лог. Если в логе `подписка не создана`, войдите заново под стримером.

**Рейды.** Когда канал рейдят, prod-бот шлёт фиолетовый анонс и шаутаут рейдеру (нужен токен стримера). Dev-бот только пишет рейд в лог, чтобы не дублировать боевого. По той же причине при переходе на этот бот старый нужно выключить.
