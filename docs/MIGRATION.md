# Переезд со старого fox-sphere на новое приложение

Простыми словами: новое приложение — это обычная папка с кодом на твоём ПК. Сервер и Docker не нужны.
Боевые данные лежат в файле `data/prod.db` (его делаешь ты, в git он не попадает).

## 0. Одна папка или отдельная?

- **Проще всего — та же папка** `C:\Dev\fox-sphere-nuxt` (это уже клон, второй `git clone` не нужен). Файлы `.env.production` и `data/prod.db` в git не попадают, dev и prod друг другу не мешают (разные порты и разные базы).
- **Спокойнее на стримах — отдельная папка**: `git clone https://github.com/LuckyFoxCode/fox-sphere-nuxt C:\Live\fox-sphere-nuxt`. Тогда можно править код в `C:\Dev`, не сломав то, что идёт в эфир. Дальше все шаги делаются в той папке, откуда запускаешь бота.

Во время стрима код не меняем и `git pull` не делаем.

## 1. Подготовка (можно заранее, старый бот при этом работает)

1. Нужны Node 22+ и pnpm 10. В папке проекта:
   ```
   pnpm install
   ```
2. Создай файл `.env.production`: скопируй `.env.example` и поправь значения так:

   | Переменная | Значение для боя |
   |---|---|
   | `NITRO_PORT` | `3000` |
   | `DATABASE_URL` | `file:./data/prod.db` |
   | `BOT_ENABLED` | `true` |
   | `OVERLAY_URL` | `http://localhost:3000` |
   | `COMMAND_PREFIX` | `!` |
   | `SOCKET_PORT` | `3002` (если dev запущен одновременно — для prod возьми `3003`, а в dev оставь `3002`) |
   | `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` | как в старом проекте |
   | `TWITCH_BOT_REDIRECT_URI` | `http://localhost:3000/auth/twitch/callback` — этот адрес должен быть добавлен в консоли Twitch байт в байт |
   | `ADMIN_SESSION_SECRET` | свой, из `openssl rand -hex 32` (или любая длинная случайная строка) |
   | `ADMIN_TWITCH_USER_ID`, `ADMIN_OAUTH_REDIRECT_URI` | как для админки (порт 3000) |
   | `INTERNAL_SECRET` | любая длинная строка |
   | `OLD_SSH_HOST` | ssh-адрес сервера со старым ботом, например `user@1.2.3.4` — нужен для переноса данных |

   `TWITCH_CHANNEL_NAME`, `TWITCH_USER_ID`, `TWITCH_BOT_ID` уже стоят правильные. Файл `.env.production` нельзя коммитить (он в `.gitignore`).
3. Создай пустую боевую базу и собери приложение:
   ```
   pnpm db:push:prod
   pnpm db:seed:prod
   pnpm build
   ```
4. Репетиция переноса данных (ничего не меняет в базе, только показывает отчёт):
   ```
   pnpm db:sync-old
   ```
   Если пишет «Расхождений в данных нет» или понятный список — всё в порядке. Старая база при этом только читается.

## 2. Момент переезда (стрим ещё не идёт)

Порядок важен, потому что данные переносятся **последним шагом перед стартом нового бота**:

1. **Выключи старого бота** (чтобы данные в старой базе перестали меняться). Старые источники в OBS пока не трогай.
2. Убедись, что новый бот не запущен.
3. Перенеси свежие данные одной командой:
   ```
   pnpm db:sync-old --apply
   ```
   Она сама: снимает дамп старой базы (только чтение), делает копию `data/prod.backup-ДАТА.db`, записывает изменения и сверяет суммы (зрители, монеты, XP). Если сверка не сошлась — запись откатывается.
4. Запусти новое приложение:
   ```
   pnpm start
   ```
   Поднимаются два процесса: Nuxt (`:3000`) и бот.
5. Бот пока не авторизован в Twitch (токены не переносятся): открой `http://localhost:3000/auth/twitch/login` и войди аккаунтом бота. После этого бот появится в чате.
6. В OBS замени адреса источников со старых на новые: `http://localhost:3000/overlay/...` (список всех — на главной `http://localhost:3000/`). Проверь в чате `!profile`, `!coins`.

## 3. Что с данными, накопленными между копиями

- Пока работает старый бот, новая база не живёт: репетиции можно гонять сколько угодно, каждая просто подтягивает свежее. Повторный запуск ничего не дублирует.
- **Балансы зрителей при каждом запуске перезаписываются значениями из старой базы.** Поэтому:
  - финальный `--apply` — после остановки старого бота и до запуска нового;
  - **после того как новый бот начал работать в бою, `db:sync-old` больше не запускать** — он затрёт новые монеты и XP старыми.
- Зрители, которых есть только в новой базе, не трогаются.
- Если стрим прошёл уже на новом боте и нужно вернуться на старого — данные назад не переносятся, это отдельная задача.
- Откат переноса: останови бота и верни копию — замени `data/prod.db` файлом `data/prod.backup-….db`.

## Если что-то пошло не так

- `pnpm db:sync-old` ругается на ssh — проверь, что `ssh $OLD_SSH_HOST` заходит без пароля/по ключу.
- Дамп не получается — проверь имя контейнера на сервере: `docker ps` (должен быть `foxsphere-postgres`, иначе задай `OLD_PG_CONTAINER`).
